WHAT EXISTS, AND WHAT DOES NOT

Existing code can supply Rust workspace conventions, primitive serialization,
and examples of login/browser/lobby services. It is not protocol compatible
by assumption. Its match server currently connects one UDP socket to one peer,
uses a different header/ack window and different message tables, and leaves
retry/fragmentation work incomplete. Its fixed 256-byte packet storage does
not fit this protocol's full transport requirements.

Known v0.21d interfaces: 12-byte UDP envelope; input 0x45 -> 0x54; clock
0x43/44/52/55; world CRC 0x46; custom snapshot 0x47; state download 0x53;
snapshot request 0x59; enter/leave 0x56/57; input discard 0x58.

Recovered during implementation (see RECOVERED-CONTRACTS.txt):
  * Reliable/ordered delivery metadata, retry identity, 64-bit ack rules,
    initial ordered ID, and transport fragmentation.
  * Static match options, roster/equipment/profile serialization and final
    local-player slot, verified against the complete captured payload.

Remaining contracts and runtime validation:
  * A usable server-created static setup with verified stock asset IDs.
  * Empty-match bootstrap and first player activation order.
  * Login/browser/lobby/messaging compatibility and direct-connect options.
  * Clock reference interpretation, offset sign, and reset/enter ordering.
  * Replay backlog requirements for late join and state replacement.
  * Exact client rollback horizon at runtime and accepted input age policy.
  * Match-end rules/results and what must be done outside local simulation.

The deployed server's arbitration is unknown. We must explicitly implement
our own recovery policy and test it, not call a guessed policy recovered.

DESIGN BOUNDARIES

Transport: a peer-specific endpoint holds send/receive sequence histories,
pending reliable data, ordered delivery, fragmented-message assembly, RTT,
last activity, and bounded queues. Sequence arithmetic must handle wraparound.

Wire codec: version-specific enums and bounded readers/writers. Separate
datagrams, transport messages, and application-level snapshot fragments.
Do not conflate an application's timestamp with transport ordering.

Match coordinator: owns session-to-slot mapping, static configuration,
monotonic match clock, accepted input history, player membership timeline,
hash observations, completed snapshots, and recovery generation. No physics.

Front door: authenticates/assigns unique local-test sessions and routes the
client to the correct match. Initially fixed profiles/stock map are acceptable;
using one hardcoded session for every player is not.

Storage/observability: event logs include peer/slot, game time, message type,
snapshot origin/time/hash, decisions and reasons. Session credentials are not
printed. Store protocol diagnostics separately from persistent match results.

ORDERED MILESTONES AND ACCEPTANCE GATES

M0. Recover the missing contracts before depending on them.
  Inspect transport metadata and packet parser/writer; annotate ack and retry
  semantics. Trace static match deserialization, connection bootstrap, and
  time synchronization. Extract representative capture messages locally.
  Produce a startup sequence diagram and field-level static payload layout.
  Gate: explain how a fresh client reaches a loaded, active player without
  copying a stale eight-player world snapshot from the captured match.

M1. Implement a standalone v0.21d codec and transport.
  Encode/decode single/bundled messages, extended lengths, ordered IDs,
  transport fragments, and snapshot fragments. Implement ack/retry/dedup,
  out-of-order delivery and bounded reassembly with expiry. Invalid/truncated
  packets must return errors without crashing or allocating unbounded memory.
  Gate: decode every captured match datagram; compare captured bytes and
  binary-derived vectors; simulate loss/reordering/duplication and u16 wrap.

M2. Reach the new local service with a real client.
  Prefer a recovered direct-connect path if it supports proper initialization;
  otherwise implement the minimum v0.21d login/browser/lobby path. Reuse older
  serializers only after proving their field layout matches. Use configurable
  loopback ports and certificates compatible with this client. Stock assets
  and deterministic test profiles reduce unrelated failures.
  Gate: the client connects to our UDP endpoint and accepts static setup.

M3. Bootstrap one fresh match, one player.
  Supply matching static seed/map/roster/options and obtain a valid empty
  snapshot from the loading client's existing patch where supported. Confirm
  snapshot/clock/activation ordering in the actual client. Activate the slot
  at an agreed 50 ms game-time boundary. Never invent health/statistics bytes
  just to get past deserialization.
  Gate: real client loads, spawns, moves, shoots, and survives normal idle
  traffic against our server; logs show no repeated reset/rejection loop.

M4. Coordinate two players.
  Unique sessions and player slots; relay timestamped inputs with the verified
  sender-echo policy. Maintain a bounded accepted-input history and membership
  events. Authenticate slot ownership from the connection, not input content.
  Clock corrections use measured latency and avoid arbitrary time jumps.
  Gate: two clients see matching movement, shots, kill/death and respawn;
  correlate hashes for identical historical timestamps and record divergence.

M5. Joining, leaving, and restoring state.
  Bootstrap policy proposal: first eligible ready client supplies the initial
  baseline; later clients receive a recent complete reference snapshot plus
  subsequent accepted input/membership history. Validate this against M0/M3.
  A snapshot is eligible only for the same match generation/static roster,
  with complete fragments and consistent timestamp/mask/size/hash evidence.
  Snapshot transfer and replay must not lose inputs arriving during loading.
  Gate: second client can join an active match; leave removes the slot on all
  clients; reference-peer exit has an explicit, tested fallback.

M6. Detect disagreement and recover without resync storms.
  Initial local-test policy: explicit reference peer, selected deterministically
  from eligible ready clients. This is new SRP policy, not a known Skhid rule.
  Compare states only at identical sufficiently old timestamps with compatible
  active membership; distinguish missing samples from actual mismatches.
  Require sustained disagreement and rate-limit requests/resets. Keep timeout
  and retry limits; never resync in response to every single old input.
  Request fresh snapshots, validate them, choose a documented baseline, and
  resync affected peers with the necessary history. A two-client disagreement
  cannot establish an honest majority. Reference trust is a test limitation.
  Gate: deliberate loss/lag or controlled divergence recovers; no endless
  reset loop, partial state adoption, or duplicated damage application.

M7. Lifecycle and usability.
  Handle disconnect, idle timeout, reconnect/session reuse, match completion,
  server restart and a clean new match generation. Determine whether result
  extraction is required for returning to the lobby; label missing persistence.
  Provide configuration, client launch steps, packet-capture instructions,
  tests and known limitations. Preserve the old server's build/tests.
  Gate: repeatable full local session and exit, plus the two-client completion
  criteria above. Commit the implementation and evidence notes on this branch.

CROSS-CUTTING CORRECTNESS REQUIREMENTS

Do not compare CRCs from different game times, rosters or match generations.
Do not treat CRC as physics validation or a decoded death report.
Do not assume one request produces a snapshot at exactly the requested time:
the community 0x59 request has no body and returns an event-horizon item.
Record actual returned time; retain matching hashes/history as needed.

Do not assume all inputs arrive once or in order. Same-time revisions exist.
Accept/reject policy, duplicate policy and relay order must be deterministic
and recorded. Enforce finite rotations, valid slots, bounded timestamp lead/
lag, and explicit handling of time/sequence wrap and stale match traffic.

Distinguish loss/retry at the transport level from replay at simulation level.
Keep full recovery snapshots immutable once selected. Abort incomplete or
conflicting reassembly; cap per-peer and total memory. Test malformed lengths,
offset overflow, duplicate/conflicting fragments, timeout, and recycled IDs.

No new kill callback is needed for basic combat. If later adding telemetry,
deduplicate/correct rollback-sensitive events; do not inject a second hit.
Do not remove animation from hashing based only on one animation-only diff.

VALIDATION LADDER

1. Byte-level vectors and malformed-input tests.
2. Full capture decode and application-message counts/state reconstruction.
3. In-memory two-peer transport under loss, reorder, duplicate and wraparound.
4. Real client startup and solo match on loopback.
5. Two real clients with controlled actions and simultaneous logs/captures.
6. Controlled latency/loss, reference departure, join and recovery.
7. Existing-server regression checks and documented repeatable launch.

Tests must validate observable contracts and failure behavior, not merely
round-trip a codec against itself. Captured vectors/binary evidence provide
independent oracles. A capture replay alone cannot prove interactive gameplay.

v0.21d recovery replay ordering under delayed snapshot delivery
2026-10-11; feature/server-v021d

RESULT AND SCOPE

The previous snapshot-ACK-before-replay sequence failed in a real two-client
test. A 1.2-second outgoing blackout during 53 delivery let the engine advance
before the server sent shooting inputs. Those inputs were rejected as too old.
This was a server sequencing bug, not a new shooting-message requirement.

The revised sequence preloads acknowledged replay before sending 53 and keeps
new replay batches flowing while its fragments are pending. The repeated fault
now delivers all three shooting inputs BEFORE snapshot completion. There are
no input-age rejections, no subsequent automatic recovery, and 712 matching
same-time CRC comparisons (zero different) after that restore. A separate test
preloaded the restoring player's own accepted inputs and produced 453 matches,
zero different. These are finite tests, not guarantees for arbitrary delay.

WHY THE ORDER MATTERS

Client process_set_time_request (0x1a2cf0) handles 52, replies with 43 and clears
world-state history. game_world_core::clear (0x1ca788) resets current/max time
to50 and full-sync cutoff to0, retaining input/event histories. change_input
(0x1cb12c) bypasses the future-time bound while state history is empty.
process_player_input_change (0x1a2f2a) still invokes it during this interval.
deserialize(buffer_reader&) (0x1cab3b) clears/restores state while retaining
those input/event histories. This permits input preload before full restore.

The alternative clock-pause idea is not implemented: 55 reads a signed 16-bit
offset and floating_timer::set_offset (0x150d70) adjusts the timer factor over
an interval. It is not an immediate set-time/pause command. 52 also clears the
world; repeatedly using it as a simple clock correction would be incorrect.

CURRENT TRANSACTION (LATE JOIN AND ACTIVE RECOVERY)

  Select a fresh, donor-CRC-corroborated populated snapshot.
  Send 52 with a unique reference; await the matching 43.
  Send accepted post-baseline input/membership events; await their ACKs.
  Repeat preload batches until none remain, then send immutable 53.
  Continue replay batches during 53 transfer, independently of state ACKs.
  Await each replay batch's ACKs before sending its successor/revisions.
  Complete only when state and replay are ACKed and no unsent events remain.

Late join then activates the new slot. Active recovery keeps the existing
membership and sends no extra enter/leave. Initial empty-cohort bootstrap is
unchanged. Both active clients' own inputs and remote inputs can be replayed.
Endpoint::has_pending distinguishes replay messages from fragmented state,
including the wire's 0xff fragment marker. A missing 53 fragment no longer
blocks replay, while the full queue barrier still gates completion.

VALIDATION AND REMAINING WORK

40 unit tests and four UDP/executable tests pass. New tests cover independent
state/replay ACK status and replay delivery during missing state fragments,
including an input revision that must wait for its predecessor's ACK. Existing
late-join/membership tests now check preload before53 and final activation only
after state completion. The inspector's optional --events output records
reassembled application delivery timestamps without credentials or chat text.

Commands (from repository root):
  cargo test -p match-server-021d
  cargo run -p match-server-021d --example inspect_match -- CAPTURE 12023 --single-match --events

Different loss/reordering patterns can still leave inputs arriving outside the
engine's history. Preloading does not freeze time after53 is applied. Large
backlogs also face the client's fixed27-entry event/input histories; the
server's10-second journal is not proof the client can retain every such event.
Recovery has bounded transfer time/attempts, but these tests do not establish
all high-latency cases, dense long-backlog safety, or a universal delay limit.
Clock correction, explicit remote death/respawn evidence, results/early victory,
and chat delivery remain unfinished at this checkpoint.

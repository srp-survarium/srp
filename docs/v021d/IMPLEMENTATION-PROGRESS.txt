1. Supervisor crash cleanup - implemented and process-tested.
   Native children use --supervised and watch stdin for supervisor EOF. Their
   grants/control sockets are removed on exit. Match-work has an exclusive
   flock inherited by every allocated child; neither service restart nor
   another allocator can claim it while an old child owns it. After all owners
   disappear, startup clears grants/sockets only in marked allocation dirs.
   Logs and unknown directories survive. Old unmarked allocations are not
   silently treated as ours. Standalone community-server lifetime is unchanged.

   Validation: 52 Python tests pass, including new workspace restart cleanup,
   inherited ownership and symlink preservation tests. Extended real-service
   lifecycle passes ordinary admission/chat/graceful restart plus killing the
   menu supervisor with SIGKILL, observing child grant/socket cleanup, then
   starting the service over marked stale crash files and retained accounts.
   Simultaneous/power loss is represented by stale on-disk files, not a claim
   that this host was power-cycled. No graphical game was launched for this.
   Logs: /tmp/srp-v021d-supervision-tests.log and
   /tmp/srp-v021d-crash-lifecycle.log (not required runtime dependencies).

2. Consistent persistent player names in game/results/chat - implemented.

3. Native SRP1 reconnect and late join - implemented; real-client acceptance pending.
   The local service preloads its sixteen immutable account/loadout descriptors,
   with initial members first and zero grants for unused identities. Running-room
   Join reserves capacity, binds a grant through the private control socket, then
   redirects the authenticated native client. Existing team/slot identity remains
   fixed for the whole generation. Arbitrary new descriptors are not supported.

   Mutations bind child instance, generation, slot, persistent account, token and
   monotonic revision. A lost response retries the same request; uncertain grants
   retain capacity. Revocation removes the old transport before same-account
   re-entry. Delayed old mutations cannot evict a newer grant. Initial and late
   admissions have bounded loading leases; observed departures free capacity.
   Finished supervised generations do not silently start another world.

   Results retain all actual participants, including departed zero-score players,
   and exclude unused descriptors. Independent review found and helped resolve
   initial-member lease leakage and phantom result participants. The final
   participation-mask implementation was reviewed with no additional findings.

   Validation: 74 Rust tests and 60 Python tests pass. The executable UDP test
   loses an admission confirmation and a populated-state fragment, then revokes,
   regrants with a new token, completes a fresh-socket handshake/restore, exchanges
   inputs again, and rejects stale grant/revoke retries. This uses synthetic
   snapshots, not an engine gameplay simulation. Real native-service lifecycle
   also passes persistent identity, admission, chat and supervisor crash cleanup.
   Logs: /tmp/srp-v021d-admission-{rust,python}.log,
   /tmp/srp-v021d-regrant-udp.log and /tmp/srp-v021d-late-lifecycle.log.

LOBBY ROUTING

Previously, one automatic redirect per account prevented finished matches
from starting again but also prevented reconnect into an ongoing match.
With --match-control PATH, the front door asks the match server for fresh
lifecycle state over its optional local Unix datagram control socket.

Request: status NONCE
Reply: v1 NONCE INSTANCE_HEX GENERATION PHASE OCCUPIED_MASK_DECIMAL

The socket remains mode0600. Requests have a random u64 nonce and a temporary
bound reply address. The connected reply socket checks nonce, version,
field count/ranges and phase, with a250ms timeout. Missing, malformed or stale
replies never authorize a redirect. The server handles at most eight control
requests per iteration; an expired reply recipient does not fail the match.

Instance identifies this server process (startup UNIX nanoseconds). Generation
starts at1 and advances when the last admitted peer is removed or a failed
cohort is reset. An ordinary departure with another peer still playing leaves
the generation unchanged. All admitted peers, including loading/restoring
ones, occupy their slot. Phase is waiting, starting, running or finished;
the configured end deadline counts as finished even before the timer tick.

The first redirect can use a free slot in waiting/running. Later redirects
for that account require the same instance AND generation, phase running,
and a free slot. A30-second lease suppresses concurrent redirects while a
client establishes its UDP connection. An idle lobby polls so it can redirect
after the old peer times out without requiring another client lobby message.
Each TCP lobby connection sends at most one redirect. Without --match-control,
the previous one-redirect-per-account behavior remains.

This is a fixed-roster local-test policy. Route identity/leases are in memory;
front-door restart does not persist them. It is not production matchmaking,
instant takeover of an occupied slot, restoration after server restart, or an
explicit user-requested new-match flow. Match order remains the fixture's1.
Chat subscriptions and account/session limitations remain in CHAT-RECONNECT.txt.

v0.21d missing-results fallback: verified client integration
2026-10-12; server checkpoint 88d4d54f4

RESULT

The separate SRP native client package-v4 already implements a usable
missing-results fallback. Its SrpResults helper watches the stock results
screen; after 15 seconds waiting it explains that statistics have not arrived
and the player can close the screen to return to Matches. The existing Close
handler remains usable. Late native statistics replace the notice normally.
There are no fabricated scores, rewards or guessed server error packets.

This resolves the results-waiting UX gap for the SRP1 client when paired with
that package. It does NOT change the older community-patched client's UI or
make an absent final donor snapshot available. That older client retains the
documented missing-results limitation. Normal results remain user-accepted.

WHY NO NEW SERVER DENIAL PACKET

The server already waits at most 10 seconds after the match deadline for a
valid final donor state, then closes the match. An absent result remains
absent when queried; it is not silently replaced with empty statistics.
The client's 15-second notice begins when its results screen starts waiting,
not at the match deadline, so these two bounds must not be conflated.

Retail on_operation_denied_received0x16f29f has no query-info error branch.
Lobby disconnect is also not an established results-error escape: the traced
on_disconnected_from_lobby0x1a2079 calls show_disconnected_message(true), and
that function0x176709 invokes root.show_sync. Merely closing the connection
would introduce another synchronization overlay, not an accurate missing-
statistics notice. Reuse the tested client UI instead of inventing a denial.
